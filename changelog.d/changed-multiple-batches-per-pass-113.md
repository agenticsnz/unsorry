**Multiple batches per dispatch pass, prefer batches over singletons (ADR-113 / SPEC-113-A, amends ADR-107).** The queue dispatcher now opens as many batch PRs as the Gate-A budget allows *before* any singleton (new `dispatch_batch_passes` loops `dispatch_batch_pass` until the governor pauses or fewer than 2 batchable branches remain), instead of one batch per pass then singletons filling every other slot. So a homogeneous backlog drains almost entirely via K-proof batches — amortising the dominant ~12–20 GB mathlib env-load over K proofs per slot instead of spending it per proof — without raising the in-flight cap. A pass-scoped exclude guards the loop against GitHub read-after-write lag re-selecting a just-batched goal; `UNSORRY_MAX_BATCHES_PER_PASS` (default 8) is a runaway backstop. Soundness, batch selection, the governor caps, and the `UNSORRY_BATCH_SIZE=1` default are unchanged. Refs #6751 (A1/A2).
