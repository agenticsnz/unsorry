A decomposed goal whose sub-lemmas are all proved but whose **recompose** (assembling them into the parent) fails is no longer stranded (ADR-115). Previously a long-running `./swarm/run.sh --prove --goal <parent>` attempted the assembly once, floored it at τ_v (ADR-034), then reported "no viable or recoverable prove work this pass" every cycle forever — the per-session `HANDLED` dedup removed the goal from both the viable and (τ_v-floored, so too-viable) recovery pools, and a manual restart only re-ran the same one-shot attempt. Now the prover **re-arms** a recompose-candidate it already tried, up to `UNSORRY_RECOMPOSE_RETRIES` times per session (default 2), so it retries the assembly up the ADR-015 effort ladder (high→xhigh→max) instead of idling; set `UNSORRY_RECOMPOSE_RETRIES=0` to restore the single-attempt behaviour. Independently, when proving a recompose-candidate the attempt prompt now carries a **RECOMPOSITION** steer telling the model the already-surfaced (ADR-014) sub-lemmas are sufficient and to assemble them (instantiate, `ring`-normalize, close with `exact`/`nlinarith`) rather than prove from scratch — the observed `aime-1983-p9` failure was a four-line glue the model missed despite having every sub-lemma. The prompt block is advisory and never gates a proof.
