`--goal <suite>` now fans out to a **curated** decomposition's children, so the "copy suite run" command from a suite page (e.g. `./swarm/run.sh --goal imo-v1-suite`) actually claims and proves the suite's problems instead of silently no-opping. Previously the scope filter (`goal_in_scope`) only matched the goal itself or machine-minted `<parent>-sN` sub ids, so a suite whose children carry arbitrary names (`imo-v1-suite` → `imo2020p2 … imo2025p6`) matched nothing claimable and the prover idled without ever taking a claim. The selector now resolves a named suite's decomposition sub-ids (a new `suite-subs` helper reading the main pool plus each `targets/<suite>/decompositions/`) and admits them into scope, alongside the unchanged suite-itself and `<parent>-sN` matches. Scope only ever widens for an explicitly-named suite; default and `<parent>-sN` selection are byte-for-byte unchanged.
