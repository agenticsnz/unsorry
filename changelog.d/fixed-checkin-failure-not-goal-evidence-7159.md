**A proof that verifies but cannot be submitted is no longer destroyed (ADR-118 / SPEC-118-A, #7159).** `prove_goal` collapsed two independent outcomes into one: `run_proof` decides whether a proof exists, `check_in_proof` decides whether its tree can be submitted, and only the first says anything about the goal. A submission-side failure — a Gate B rejection, a lost push race, a PR that would not open — therefore fell through to the ADR-009 decompose-on-failure path, discarding a kernel-verified proof and minting sub-goals that ADR-018 makes **permanent** (`gate-a-prepare` rejects goal deletions). It happened twice on the same tree: #7133 added an irreversible extra level under `aime-1983-p9-s1`, and #7151 discarded a proof of `-s2` that had verified on attempt 1, opening an auto-merge-armed decompose PR that was closed by hand seconds before it landed. Fixing the specific trigger (#7158) did not remove the mechanism; Gate B gains rules over time, so any future rejection of a valid tree would have done it again. A check-in failure following a successful `run_proof` is now treated as the ADR-016 no-penalty class — no `prove-failed` event, no decomposition, no demote, claim released, reported to `supervise` as an infrastructure-class outcome so it backs off and surfaces the condition rather than making forward progress that is really damage. Genuine prove failures still decompose exactly as before, covered by its own regression test. Separately, both Gate B call sites discarded the validator's output, leaving `fails Gate B` as the only diagnostic; they now print the violating rule ids and paths.
