The flaked-gate retry janitor (ADR-112) now **falls back to `update-branch`** when a rerun is rejected. GitHub refuses to re-run a workflow run older than a few days, so a queued proof branch that flaked days ago and only now got dispatched as a PR could never be rerun ("This workflow run cannot be retried") — it sat `BLOCKED` despite a sound proof. The janitor now rebases such a PR onto current `main` (fresh `synchronize` → gates re-dispatch on a current SHA), the same recovery the dropped-gate janitor uses. Needs the admin `REFRESH_TOKEN` for the synchronize to re-trigger; `--no-rebase` keeps it rerun-only otherwise.
