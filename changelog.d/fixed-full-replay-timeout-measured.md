**`gate-a-full-replay`'s timeout is raised from 180 to 360 minutes on the measured cost of a GitHub-hosted run (ADR-117 follow-up).** A dispatch run on `ubuntu-latest` (30424360687) settled what the port left open: setup, the mathlib build, the `--wfail` library build and the **full axiom audit** all completed in **38 minutes**, so the port itself is sound. The serial `Full kernel replay` step (`--jobs 1`, `UNSORRY_REPLAY_CHUNK=6`) then ran for **143 minutes and was cancelled incomplete** by the 180-minute cap. Because that step emits no progress output, its true duration is unknown — only that it exceeds ~143 minutes on 4 vCPU. 360 is GitHub's hard ceiling for a hosted job, so this is the largest cap available: if the replay does not fit within it, raising the number again cannot help and the answer is sharding the replay across matrix jobs, or raising `--jobs` (bounded by leanchecker's memory rather than by cores, which is why the chunk is small and a best-effort swapfile is added). This remains a measurement rather than a known-good value, and is recorded as such in the workflow.
