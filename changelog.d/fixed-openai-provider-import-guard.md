**`python3 -m pytest tools -q` works on a machine without `requests`.** `tools/llm_providers/openai_provider.py` guarded its optional dependency with `except ImportError: sys.exit(1)` at module scope. That aborted the interpreter *during import*, which took pytest's entire collection phase down with it: the command `CLAUDE.md` documents died with `INTERNALERROR ... SystemExit: 1` and reported nothing about the ~1200 tests that never touch `requests`. CI never caught it because `gate-b` runs three narrower paths. The failure is now deferred to `OpenAIProvider.__init__`, which raises `OpenAIError` — the CLI already maps that to a clean exit 1, so an operator running the provider sees the same message and status as before. Two test modules that genuinely need the dependency now skip rather than error: `test_openai_cli.py` via `pytest.importorskip`, and the seven provider-construction tests via a `skipif` marker (not a module-level `importorskip`, because the new missing-dependency tests must still run precisely when it is absent). Measured with `requests` blocked: the suite went from **0 tests reported** to **1200 passed, 10 skipped, exit 0**.
