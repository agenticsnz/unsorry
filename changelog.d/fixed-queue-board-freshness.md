The queued-proofs board now refreshes on a **proof merge** (a `push` to `main` under `library/index`), not just the `*/15` cron — GitHub throttles the schedule under load, so the board could show a pre-drain count for hours after proofs landed (e.g. a solver stuck at 141 waiting while their solves were already on `main`). It also stamps `generated_at` (keyed to the latest board-source commit, deterministic — no timestamp-only churn) so a frozen board is visible as stale rather than mistaken for a quiet queue (ADR-066).
