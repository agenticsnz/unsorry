**Harden PR auto-merge arming so green prove PRs can't strand (ADR-005 / ADR-105 / ADR-107).** Two defence-in-depth fixes for the finalization gap that stranded 40 green PRs: (1) **creation-time arm** — the dispatcher's `gh pr create && gh pr merge --auto …` chain silently left a PR un-armed whenever `--auto` was rejected ("PR already in clean status" race) or hit a transient error, *and* treated that as a hard dispatch failure. It now goes through `arm_or_merge_pr`, which arms auto-merge, falls back to a direct merge when the PR is already mergeable, and never fails the dispatch (a created PR is left for the recovery janitor on a transient error). Used by all three sites (same-repo + queued singletons → `--squash`, batches → `--merge`). (2) **batch recovery net** — a green-but-unarmed *batch* PR previously had no backstop (`finalization-recovery`'s `should_arm` only matches `prove(`, not `prove-batch(`); `batch-recovery-janitor` only handled failures). The batch-recovery-janitor now also arms green-but-unarmed batch PRs with `--merge`. Refs #6751.
