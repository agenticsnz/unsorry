A benchmark goal's prove no longer spuriously fails (and needlessly decomposes) when the provider drops a scratch file under the suite `_verify` build dir. The proof-target path guard (`prove_target_only_changed`) auto-removed untracked provider scratch files only at the repo *root*, but a benchmark goal proves inside `targets/<suite>/_verify/` (ADR-099/ADR-116), so the model's helper files (e.g. an axiom-check scratch `.lean`) landed there, tripped the guard, and — because the prove "failed" — decompose-on-failure split a trivial sub-lemma. The guard now also tolerates (and removes) untracked strays under the goal's suite `_verify` dir, while untracked files in package/spec/tooling trees and any tracked-file edit remain hard violations.
