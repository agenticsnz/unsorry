A new `swarm/cleanup.sh` reclaims the swarm's **local disk footprint** — the throwaway state a long-running prover accumulates *outside* the repo, which is what fills a small box (e.g. a codespace volume), not anything tracked in git. It reclaims the stale per-goal git worktrees under `$UNSORRY_WORKDIR` (`prove-`/`converge-`/`pr-`/`decompose-`/`demote-`/`telemetry-<goal>-<agent>`, one full checkout each), the nanoda Rust build tree under `$UNSORRY_INDEPENDENT_CHECK_DIR` (keeping only `target/release/nanoda_bin`), and the cargo/pip package caches. It is **dry-run by default** — it prints what each category would free and deletes nothing — with `--apply` to delete, `--deep` to additionally clear rebuild-triggering state (the repo's `.lake/build` and stale elan toolchains), and `--force` to remove worktrees even while a swarm looks live (the default skips them so a mid-proof worktree is never pulled out from under a running prover). The keepers — the `claims-branch` worktree and the nanoda/lean4export binaries — are never touched. Wired into the `agent-lint` gate (shellcheck + `bash -n` + a hermetic `--self-test`).
