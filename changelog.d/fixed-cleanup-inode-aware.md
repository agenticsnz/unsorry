`swarm/cleanup.sh` is now **inode-aware**, fixing the case where it reports `Total reclaimable: 0B` on a box that is actually *out of inodes* — `mkdir` failing with `ENOSPC` while `df` still shows free bytes. The swarm's footprint is millions of tiny files (mathlib `.olean` trees, loose git objects), so inodes exhaust long before bytes, yet the old script counted bytes only. Every category now reports an inode count beside its byte size, the run prints a `df -i` pressure warning (tunable via `UNSORRY_INODE_WARN_PCT`, default 80), and `--deep` additionally packs loose git objects (`git gc --prune=now`, swarm-gated like worktree removal) — previously the single largest inode hog and the one thing `cleanup.sh` never reclaimed. Worktree removal also no longer relies solely on the name-prefix allowlist: it reclaims any **git worktree registered under `$UNSORRY_WORKDIR`** (except the `claims-branch` keeper), so a scratch checkout whose directory name dodges the prefixes is no longer left behind, and any remaining unreclaimed inode hog is surfaced with a note instead of being hidden as `(none)`.
