**Recorded that `agent-lint` is advisory, not gate-enforced (#7159 follow-up).** SPEC-007-A stated a "Quality bar" of shellcheck-clean / `bash -n` clean / hermetic self-test green, and listed it under Acceptance criteria, without noting that nothing enforces it: `main`'s branch protection requires only `gate-a` and `gate-b`, so a PR whose `agent-lint` is red still auto-merges under ADR-005. That is exactly what happened to #7180, which landed a shellcheck regression in `swarm/agent.sh` (fixed in #7182). The bar itself is unchanged and remains the standard the harness scripts are held to — the spec and the workflow's own header comment now say plainly that it reports rather than blocks, and that `shellcheck swarm/agent.sh` is worth running locally. Keeping the check advisory was a deliberate call: `swarm/` is already code-owner-gated under ADR-019, and making the linter required would add a blocking gate to the autonomous merge path over findings that are often cosmetic.
