Benchmark obligations (ADR-099) can now be **decomposed and recomposed at the suite pin** (ADR-116). When decompose-on-failure (ADR-009) splits a benchmark obligation, its sub-lemmas now inherit the parent's suite verifier context — `suite_context_for_goal` resolves a goal to a suite not only when it is the suite `top` or a `skeleton.aisp` obligation but also when it is a **decomposition-descendant of one** (walking the sub→parent graph). So a sub proves at the suite's own toolchain + mathlib (not the repo pin) and stages as a suite-local helper module, and `proved-deps` for a benchmark recompose now reads the **suite** library — where those sub-modules actually live — instead of the repo library, so the parent can find them and assemble. This unsticks the recompose→floor→retry loop that trapped benchmark obligations like `aime-1983-p9` (whose subs had been proved at the wrong pin and could never be reused). The curated obligation set and its leaderboard count are untouched — helpers are library modules, not obligations. Organic (non-benchmark) decomposition is byte-identical to before.
