The sharded axiom audit (ADR-091) no longer crashes when two benchmark goals in the same shard share a top-level declaration name. Ten IMO answer-blank goals (`imo2020p5`, `imo2022p5`, … `imo2025p6`) each declare a bare `def answer`, and ADR-018 freezes their `.lean` files — so when a full audit's `split_evenly` co-located two of them in one shard, the single `axiom_audit --allow-sorry` import failed with `environment already contains 'answer'`, reddening the whole gate (surfaced by #7117, whose `gate-a.yml` edit forced a full audit). The serial `audit` path already guarded this with `collision_free_chunks`; the sharded `audit_shard` now does too, packing each shard's goals into collision-free groups (greedy first-fit, a new import opens only on a real name clash, so a no-clash shard stays a single call). Soundness-neutral — a declaration's axioms depend on its own import closure, not how it is batched — and coverage is unchanged (every module still audited exactly once).
