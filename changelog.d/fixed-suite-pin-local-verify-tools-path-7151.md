**Benchmark sub-lemmas can now pass local verification at the suite pin (ADR-116, #7151).** `prove_local_verify`'s third step, `python3 -m tools.gate_a.check_library_options`, resolves `tools` from the current working directory, but the function ran it in the *build* dir — which for a benchmark goal is the suite `targets/<suite>/_verify` project, where no `tools/` exists. The check died with `ModuleNotFoundError: No module named 'tools'`, so **every** suite-pin proof failed local verification however correct it was: the proof module built clean, the ADR-011 binding built clean, and the attempt was still rejected. Steps 1–2 now run in the build dir and step 3 runs in the repo root against an explicit library path, matching the contract already documented above the function (`check_library_options <root>/library`); an organic goal's four-argument call is byte-identical to before. The failure output fed back to the next effort rung (and persisted as an ADR-024 lesson) now covers step 3 as well — previously a step-3 failure reported the step-1 build's output, handing the model `Build completed successfully` as the reason its attempt had failed, which no fix could satisfy. Observed on `aime-1983-p9-s2`, the first goal ever to exercise the ADR-116 path.
