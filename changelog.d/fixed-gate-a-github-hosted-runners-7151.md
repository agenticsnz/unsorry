**Gate A runs on GitHub-hosted runners again (ADR-117 / SPEC-117-A).** The namespace.so trial ended, leaving zero runners on `namespace-profile-unsorry-1`, so every Lean-touching Gate A job queued forever and no proof could merge — the exact hazard ADR-058's lane consolidation was meant to prevent. The outage stayed invisible for a while because `detect`'s `lean` path filter skips the heavy jobs, so PRs touching only Python or shell still merged normally; the first proof PR was what surfaced it. All four Gate A profiles now target `ubuntu-latest`, free and unlimited on this public repository. The cache path needed no code change at all: ADR-046's failsafe classifies any non-`namespace-*` label as `*_volume=false`, which switches each job off the Namespace `.lake` volume and onto the ADR-045 `actions/cache` path automatically. Benchmark proof PRs are unaffected by the weaker hardware — they touch `targets/<suite>/_verify/**` and `.aisp` records, which `detect`'s `active` filter does not match, so the full repo-library build is skipped and only the suite build runs. Three scheduled workflows (`lake-volume-janitor`, `gate-a-full-replay`, `independent-check-backstop`) still carry the Namespace label and will accumulate queued runs; none gates a merge, and each needs its own disposition — `lake-volume-janitor` in particular maintains a volume that no longer exists. `gate-a-prepare`'s cap also rises from 45 to 120 minutes — the value the other heavy Gate A jobs already use. A cold library build does not fit in 45 minutes on the 4-vCPU lane (measured: `[9150/10062]`, ~91%, still compiling cleanly when the cap killed it), and because `actions/cache` saves in a post-step that a cancelled job never reaches, a timed-out cold build seeds no cache and guarantees the next run starts cold too.
