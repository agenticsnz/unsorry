**Archive re-validation reuses the repo's dependency tree instead of cloning a mathlib per package, unblocking the ADR-048 daily backstop (#7209).** The scheduled `gate-a-full-replay` step that re-validates every `packages/unsorry-archive-*` had never actually executed — it was `skipped` on every run because the kernel replay ahead of it always died first. Its first-ever execution (run 30520185283) failed with `No space left on device`, and structurally so: a base-less scheduled run has no diff, so neither the provenance check nor the `only_index_metadata_changed` fast-path applies, and all **134** archive packages each ran `lake exe cache get` + `lake build` in their own Lake project, cloning their own mathlib. The code already recorded this hazard for wide metadata PRs (#3218); the scheduled path hit it unconditionally. Since an archive package is a snapshot of the active repo (ADR-041), all 134 pin the identical toolchain (`leanprover/lean4:v4.30.0`) and the identical mathlib (`c5ea0035`) — the same ones the repo itself builds — so the fetch was pure duplication. `shareable_packages_dir` now links a package's dependency directory at the repo's already-built `.lake/packages` when **every** toolchain and dependency pin matches exactly, skipping the per-package mathlib fetch; on any mismatch (a toolchain bump would split the archive set from the active repo) it falls back to the package's own clone rather than silently building an archive against a mathlib it was never verified with. The link is removed after validation whether it succeeds or fails, and only the link — never the shared tree behind it. Measured on a real archive package: build via the shared tree completes in ~40 s with no mathlib fetch at all.
