The flaked-gate retry janitor (ADR-112) now **rebases first when a blocked PR's branch is behind its base** (ADR-114 / SPEC-114-A). Re-running the same head SHA clears a *transient* flake but not a *base-staleness* failure: when a branch falls behind `main`, `gate-a-prepare`'s published-olean cache key is superseded, so it cold-builds the whole library and hits its 45-min `timeout-minutes` — and a rerun of the same stale SHA reproduces that deterministically until the PR is parked `BLOCKED` for a human (observed: #7056, 2 commits behind `main`, repeated 45-min cold-prepare timeouts). A new pure `recovery_action(behind_by, no_rebase)` picks `update-branch` (warm cache → re-dispatch on a fresh SHA) when the branch is behind and a rebase token is available, else the unchanged rerun path. No workflow change and no regression without `REFRESH_TOKEN` (`--no-rebase` keeps it rerun-only). Recovery, not prevention — the cold-prepare fix itself is tracked in #5751. Refs #5751, #1921, #7056.
